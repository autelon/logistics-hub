**표준상 단계 커버리지 요약**

- 도착/도크(입하): **전용 표준 메시지 없음**(X12 944/861, RECADV 모두 "검수 후" 발신 전제). 도착 통지는 운송 측 메시지(IFTMAN 등)의 영역 — 미확인.
- 검수 결과: 861 RCD 조건코드, RECADV QVR/4221 코드로 **입고 통보 메시지 안에 포함**(별도 메시지 아님).
- 입고확정(재고 전기): 944(창고→화주), 861(구매자→공급자), RECADV = 핵심 메시지. 모두 **1건의 메시지에 품목별 "수령수량 + 차이수량 + 사유코드"**가 표준 granularity.
- 적치(putaway)/로케이션: 표준 메시지 없음. 944 W07에 창고 로트는 있으나 **빈/로케이션 요소 없음**(확인).

**보편적 합의 (Q1)**

1. 화주에게 보이는 정식 이벤트는 **"입고확정(GR/receipt confirmation) 1건"**이며, 그 안에 품목별 수령수량 + 차이수량 + 사유코드가 들어간다(944 W07/W14, 861 RCD, RECADV QTY194+QVR, EWM GR→ERP, Oracle Verify→host). 확인.
2. **도착/도크·검수 중·적치는 WMS 내부 상태**로만 존재하는 것이 일반적이다. 예외: 풀필먼트형 API(Amazon CHECKED_IN/RECEIVING, ShipBob Arrived/Processing)는 조회용 상태로 도착·처리중을 노출하고, Oracle Fusion Receiving은 DELIVER(적치) 트랜잭션까지 인터페이스로 받는다. 확인.
3. 로케이션/빈은 표준 메시지에도, 풀필먼트 API에도 노출되지 않는다(944는 창고 로트만). 확인.
4. 부분입고는 **동일 ASN에 대한 복수 확정(부분 GR 반복)**으로 처리하고, 최종 종결 플래그(EWM final delivery indicator, D365 multiple product receipt per load, Oracle Receiving Started→Verified)로 닫는다. 확인.
5. ASN 없는 입고는 모든 시스템이 지원하되(EGR, PO 기반 등록, blind LPN) **"ASN 없음"을 상태/코드로 표기**한다 — X12 412 코드 13/14/16이 표준 차원의 증거. 확인.

**특수 상황과 대응 (Q1)**

- 초과입고: 허용오차 %로 경고/차단 2단계(Oracle Warning/Error, EWM DTL, D365 Allow/Block, Fusion None/Warning/Reject). 확인.
- 파손/품질보류: 재고 상태(stock type / inventory status / QC LPN)로 분리하고 수량은 입고하되 가용에서 제외. 861 코드 09 Hold, 944 W14-03 damaged/on-hold. 확인.
- 블라인드 수령 후 ASN 도착: Manhattan은 자동 매칭. 확인(매장 솔루션).
- 입고 후 정정: X12 947(재고조정 통보), 944 W07-09 역분개 코드, EWM 취소 시 정정 자재문서. 확인.

**보편적 합의 (Q2)**

1. 제조사 시리얼 리스트는 **ASN(856 REF\*SE / DESADV GIN)과 함께 전달**하는 것이 표준 경로이며, 입고 통보(944/861/RECADV)에 시리얼을 되돌려 보내는 **표준 요소는 약하거나 없다**(944 W07 없음, RECADV GIN은 SSCC 용도). 확인.
2. 시스템들은 ASN 시리얼을 **기본값(default)**으로 쓰고, 수령 시 스캔으로 덮어쓸 수 있게 한다. **불일치 시 차단보다 "검증 + override 허용(플래그)"이 주류**이고, 강제 일치는 명시적 설정(Oracle validate, Fusion RMA)에 한정. 확인/추정.
3. 공통 하드 룰은 "**시리얼 개수 = 수량**"(Oracle) 및 "필수 프로파일이면 시리얼 없이 GR 불가"(SAP). 확인.
4. 입고 시 시리얼 미캡처·출고 시만 캡처 모드가 공식 옵션으로 존재(D365 Active in sales process / Capture at Picking·Packing, Oracle Track only at Packing). 확인.
5. 풀필먼트형 3PL API(Amazon, ShipBob)는 시리얼 자체를 다루지 않는다. 확인.

**특수 상황과 대응 (Q2)**

- ASN 시점 시리얼 미확정: Oracle PROMPT_IF_NOT_KNOWN(ASN에 없을 때만 프롬프트), D365 입고 시 캡처. 확인.
- 재작업 후 시리얼 교체: EWM "임시 시리얼은 최종 빈 WT 확정 전까지 교체" 규칙 존재(확인); 그 외 시스템은 미확인.
- 중복 시리얼: 유니크 범위(품목 내 vs 전역) 설정은 이번 조사에서 1차 문서 미확인 → **미확인**.
- 형식 검증: GS1 AI(21) 20자·허용문자셋이 유일한 표준 근거(확인); 시스템별 마스크 검증은 미확인.
