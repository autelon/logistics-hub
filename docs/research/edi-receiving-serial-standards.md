## Q1-2. 보편적 합의 (표준 간 공통점)

1. **보고 단위는 "라인(품목) × 수량 × 상태코드"가 기본, 포장(SSCC/LPN) 단위는 선택.** X12 944는 W07(품목·총수량·로트)+W13(예외수량·412코드), 861은 RCD(수령/수락 수량 + 최대 5쌍의 문제수량·412코드), EDIFACT/EANCOM는 LIN+QTY(48/194)+QVR(195/196 + 4221/4295 사유), GS1 XML은 lineItem(quantityReceived/quantityAccepted + receivingConditionInformation). 포장 단위는 EANCOM CPS-PAC-GIN(SSCC) 또는 LIN 하위 PCI-QTY-QVR-GIN(SSCC별 수량), GS1 XML receivingAdviceLogisticUnit(sscc), X12는 N9*QQ/97·MAN. **[확인]**
2. **"받은 수량"과 "수락한 수량"을 구분한다.** EDIFACT 48(received) vs 194(received and accepted) vs 195/196(received, not accepted → 반품/폐기), X12 861 RCD02(received or accepted) vs RCD04(returned) vs RCD06(in question), GS1 XML quantityReceived vs quantityAccepted. 944는 W0701이 "파손 포함 총수령"이고 W13으로 예외를 분리, W1403으로 Damaged/On Hold 합계. **[확인]**
3. **불일치 어휘는 사실상 공통**: 파손(01 / AF·124 / DAMAGED_…), 부족(02 / BP·CP·195 음수 / QUANTITY_SHORT), 과입고(03·12 / AC·121 / QUANTITY_OVER[_RETURN_TO_SUPPLIER]), 거절(08 / 185·195·196 / REJECTED), 보류(09 / HOLD), 오품(05 / BJ·IS / INCORRECT_PRODUCT·SUBSTITUTED_ITEM), 양호(07 / GOOD_CONDITION). GS1 XML 코드리스트는 X12 412를 그대로 이식한 형태. **[확인]**
4. **입고통보는 "물리 수령 + 검수 후" 1회 송신이 원칙**(EANCOM: "after the goods are physically received and inspected", 합의 기간 예 24h). 수정은 BGM 1225=5 Replace + RFF ALO(이전 통보번호), X12는 BRA03 purpose code. **[확인]**
5. **입고통보는 ASN/주문을 참조**(RFF AAK/ON, X12 W1704/W1705·PRF, GS1 XML despatchAdvice)하고, 재고 수불의 후속 변동은 별도 메시지(X12 947, EANCOM INVRPT)로 분리. **[확인]**
6. **EPCIS는 메시지가 아니라 이벤트 모델**로서 arriving/accepting/receiving/inspecting/holding/unpacking/storing을 개별 bizStep으로 제공하고, 수량·개체 불일치는 disposition(mismatch_quantity/instance/class)으로 표현하며 desadv/recadv 문서를 bizTransaction으로 링크한다. **[확인]**

## Q2-2. 보편적 합의

1. **출하(ASN) 측은 시리얼을 "개별 열거 또는 범위"로 보낼 수 있다.** X12 856은 REF*SE 1개=시리얼 1개(범위 표기 없음; SSCC는 MAN02/03 범위 가능), EDIFACT DESADV GIN+BN은 연속 범위(C208 두 7402) 또는 개별값(5개/세그먼트). **[확인]**
2. **입고 측 표준은 시리얼 회신을 "허용"하지만 "요구"하지 않으며, 수단은 표준마다 다르다**: X12 944 N9*SE(라인당 200개), X12 861 REF*SE/MAN, GS1 XML serialNumber(무제한, 20자), UN/EDIFACT RECADV GIN(BN 가능) — 단 **EANCOM RECADV는 GIN을 SSCC로 제한**해 품목 시리얼 회신이 없음. 표준 어디에도 "ASN 시리얼과 수령 시리얼의 매치/미싱/언익스펙티드"를 코드화한 EDI 요소는 없고, 수량 차이(QVR/W13/RCD) 또는 4295 BJ "Item identification code unknown"·412 05 "Incorrect Product" 같은 일반 불일치 코드로 우회한다. **[확인]**
3. **개체 수준 불일치를 명시적으로 표현하는 유일한 GS1 표준은 EPCIS/CBV**(mismatch_instance/class/quantity, persistentDisposition). **[확인]**
4. **시리얼 식별자 규격은 GS1 AI(21)으로 수렴**: 영숫자 최대 20자(82자 집합), **GTIN과 결합해서만 유일**(단독 유일성 아님), 제조사/브랜드오너가 부여, 수명 동안 고정. 바코드는 GS1-128/DataMatrix(AI 01+21[+10+17]), RFID는 SGTIN-96(숫자만)/SGTIN-198(영숫자). **[확인]**
5. **WMS 공통 동작**: (a) 시리얼 관리 품목은 "수량 = 시리얼 개수"를 강제(Oracle 명시, SAP는 "Quantity differs from number of serial numbers" 오류 **[미확인: 커뮤니티]**); (b) 창고/제품 범위에서 **중복 시리얼은 차단**(SAP /SCWM/DLV_SERIAL208, 제품+시리얼 조합 유일); (c) ASN 시리얼은 "기대값"으로 복사되며 **GR 확정 전까지 수정 가능**(SAP 명시); (d) 대조 강도는 설정값(Oracle Don't validate / Validate / Validate+override, Oracle PROMPT_IF_NOT_KNOWN). **[확인]**

### 핵심 결론 요약

- **Q1**: 창고→화주 입고통보는 X12 944/861, EDIFACT RECADV(EANCOM/GS1 XML)로 **"입고확정(GR) 시점의 라인별 수령·수락·예외수량+상태코드"**를 보고하는 것이 보편이며, **도착·검수·적치 단계는 전용 EDI 메시지가 없고** 861 BRA04(1/2/3/8), RECADV DTM 178/50, CBV bizStep(arriving/inspecting/storing)으로만 구분된다. 부분 입고는 수량차+BP/CP(또는 purpose code/누적수량)로, ASN 없는 입고는 412 13/14/16·4221 AE·4295 BO로 표현한다.
- **Q2**: ASN은 시리얼을 개별(856 REF*SE) 또는 범위(DESADV GIN BN)로 보낼 수 있고, 입고통보는 944 N9*SE·861 REF*SE·GS1 XML serialNumber로 회신 가능하나 **EANCOM RECADV는 SSCC까지만** 지원한다. ASN-수령 시리얼 대조 결과를 코드화한 EDI 표준은 없으며 EPCIS CBV의 mismatch_instance가 유일한 표준 표현이다. WMS는 공통적으로 "수량=시리얼 수" 강제, 제품(+창고) 범위 중복 차단, GR 전 수정 허용, 대조 강도는 설정(Oracle validate/override, D365 capture 시점, SAP 요구 레벨)으로 처리한다.
