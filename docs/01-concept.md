# 1. 컨셉

## 한 문장

> 실행은 각 업체 시스템이 하고, 우리는 **물리 제품 하나하나에 실제로 무슨 일이 있었는지에 대한 믿을 수 있는 기록**을 가진다.

업계 용어로는 **Supply Chain Control Tower / Visibility Platform** 에 가깝다. SAP 같은 ERP 가
"계획하고 지시하는 시스템"이라면, 이 시스템은 "여러 업체에 흩어진 실행 결과를 모아 하나의 진실로 만드는 시스템"이다.

## 이 시스템이 하는 것과 하지 않는 것

| 한다                                                     | 하지 않는다 (업체·채널 시스템의 일)      |
| -------------------------------------------------------- | ---------------------------------------- |
| 업체가 보고한 사실을 제품(시리얼) 단위로 기록            | 창고 피킹·적치 지시, 생산 지시 (WMS/MES) |
| 틀린 보고를 **지우지 않고** 정정, 정정 이력 보존         | 업체 시스템의 데이터 수정                |
| 정정이 반영된 재고·자산 현황 제공                        | 배차·운송 실행 (TMS)                     |
| 채널 주문을 받아 "어떤 물리 제품이 나가야 하는가"로 풀기 | 결제, 환불, 환불 사유, 고객 응대         |
| 어느 주문의 어느 패키지에 어떤 시리얼이 나갔는지 연결    | 상품 전시, 가격, 프로모션                |
| AS 시스템의 DOA 판정·폐기를 제품 이력과 주문에 반영      | 수리 접수·진행 관리 (AS 시스템)          |

## 세 가지 원칙

### 1. 보고된 사실과 유효한 사실을 구분한다

업체 직원이 시리얼을 잘못 스캔하면 업체 전산에는 틀린 정보가 남고, 그쪽에서는 못 고치는 경우가 많다.
우리는 그 보고를 **그대로 받아 적되**, 틀렸다는 것이 확인되면 "이 기록은 무효, 사유는 이것, 처리자는 누구"라는
정정 기록을 덧붙인다. 원본은 남는다. 현재 상태는 언제나 **무효가 아닌 사실들만** 접어서 만든다.

회계 장부에서 틀린 분개를 지우지 않고 역분개하는 것과 같은 방식이다.

### 2. 거부하지 않고 표시한다

"재고에 없는 제품이 출고됐다"처럼 순서가 말이 안 되는 보고가 와도 거부하지 않는다.
현실에서 이미 일어난 일이고, 거부하면 우리 기록만 현실과 멀어진다.
받아서 상태에 반영하고, **이상(anomaly)** 으로 표시해 사람이 확인하고 정정하게 한다.

### 3. 제품 한 개가 추적의 단위다

모든 기록의 중심은 시리얼 번호가 붙은 물리 제품 한 개다. 주문, AS 케이스, 거점은 그 제품의 이력에 붙는 참조다.
그래서 "이 시리얼은 언제 만들어져, 어느 창고에 있다가, 어느 주문의 어느 패키지로 나가, 언제 불량 판정을 받고 폐기됐나"를
한 번에 답할 수 있다.

## OMS 는 SCM 의 일부인가?

아니다. 다만 흔히 말하는 OMS 전체를 만드는 것도 아니다.

일반적인 OMS 는 주문 접수·결제·취소·환불·CS 까지 다룬다. 여기서 필요한 것은 그중 **주문과 물리 재고를 잇는 부분**,
업계에서 **Distributed Order Management(DOM)** 또는 **Order Fulfillment** 라고 부르는 영역이다.

- 판매 채널(네이버 스마트스토어 등)이 주문의 주인이다. 결제·환불·정책은 거기 남는다.
- 우리 OMS 는 주문을 넘겨받아 **출고해야 할 물리 제품 목록**으로 바꾸고, 각 항목에 실제 시리얼이 붙어
  배송 완료될 때까지를 추적한다.
- 재고·제품 이력의 주인은 SCM 이다. OMS 는 SCM 이 내보내는 이벤트로만 출고·배송 사실을 안다.

그래서 서비스는 나누되(`scm-api`, `oms-api`), 이벤트로 느슨하게 연결했다. AS 도 같은 방식이다.

```
판매 채널 ──주문──▶ OMS ──출고 요청──▶ (창고 연동) ──출고 보고──▶ SCM
                     ▲                                             │
                     └────────── 출고·배송·정정 이벤트 ◀────────────┘
AS 시스템 ──DOA 확정·폐기 이벤트──▶ SCM (제품 이력), OMS (교체 출고)
```
