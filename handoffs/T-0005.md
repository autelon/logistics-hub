### PRD "개발사항" 초안

- 선적 무효화: `POST /shipments/:shipmentNo/void { actor, reason }`. 모르는 선적 `SHIPMENT_NOT_FOUND`, 이미 무효화된 선적 `SHIPMENT_ALREADY_VOIDED`. 처리자·사유·시각을 `shipment_corrections` 에 추가하고 선적 행은 바꾸지 않는다.
- 무효 선적은 선적 수량 누계와 "이미 알려진 시리얼" 조회에서 빠지고, 차수 번호를 셀 때는 계속 센다. 다시 제출한 선적은 새 차수 번호를 받고 `OVER_SHIPPED`·`DUPLICATE_SERIAL` 이 잘못 붙지 않는다.
- 그 선적이 만든 `DISPATCHED` 사실을 정정한다(종류 + 출처 참조가 지금 번호 또는 연결 전 번호 + 이 선적의 시리얼). 이미 정정된 사실은 건너뛰고 건수를 돌려준다. 시리얼마다 `scm.unit.event-voided`(규격 변경 없음). 활성 여부가 바뀌면 기기 요청 `DEACTIVATE` 를 무효화 한 번에 하나, 사유 `SHIPMENT_VOIDED`.
- 무효 선적에 대한 연결 명령과 선적 단위 제품 등록은 거절한다. 조회는 되고 `voided`·`voidRecord` 로 보여 준다.
- 잠금 순서는 입고와 같은 발주 → 선적 → 개체. 읽은 뒤 연결로 발주가 바뀌면 처음부터 다시 한다.
